# Art Direction

## Purpose

This document defines the creative direction of Matthew Blanke's portfolio.

It is not a component specification.
It is not an implementation guide.
It is not a motion API reference.

It answers:

> What should the portfolio feel like?

The visual system should remain recognizably Matthew's even when individual chapters use different project-specific colors, objects, or interaction patterns.

---

# Core Direction

The portfolio is a **clean, high-end interactive experience interrupted by intricate visual objects and motion**.

The base should feel:

- minimal
- precise
- sleek
- spacious
- modern
- technically sophisticated
- visually calm

The focal moments should feel:

- unexpected
- dimensional
- authored
- intricate
- playful
- spatial
- memorable

The guiding phrase is:

> **Minimal interface. Maximum choreography.**

A second guiding rule is:

> **Clean base. Intricate focal points.**

The portfolio should never feel busy simply because it can.

# Overall Visual Character

The site should feel more like an interactive design object than a conventional website.

It should avoid obvious web-template structure.

The visitor should not constantly see:

- containers
- section wrappers
- card grids
- UI chrome
- repeated button blocks
- repeated text-image modules

Instead, the page should feel like a sequence of composed scenes.

Each scene should have a dominant visual idea.

Examples:

- a large name and a single sculptural object
- a project represented by one dimensional interaction
- a giant year used as visual architecture
- academic clusters assembling spatially
- a still-life of personal objects
- a quiet contact scene

The design should feel intentional even when motion is paused.

---

# One Idea Per Viewport

A core visual rule:

> **One primary idea per viewport.**

This does not mean every section must be exactly one viewport tall.

It means the visitor should always know what the dominant visual concept is.

Avoid placing:

- multiple competing illustrations
- several card clusters
- many simultaneous calls to action
- dense metadata
- large text blocks

in the same visual moment.

Hierarchy should be obvious.

---

# Typography

Typography should be structural, not decorative.

Large type may:

- define the viewport
- frame an object
- overlap imagery
- crop against the viewport edge
- persist through a transition
- become a spatial element

The display face should feel contemporary, strong, and clean.

The body/UI face should be highly readable and visually quiet.

Exact typefaces are not yet locked.

Do not inherit fonts from the previous portfolio merely because they already exist.

Typography should be selected specifically for this direction.

---

# Type Scale Philosophy

The site should use strong contrast in scale.

Possible hierarchy:

- monumental display words
- medium scene descriptors
- very small supporting metadata

Avoid an overly smooth scale where everything feels similar.

Large type should often feel much larger than conventionally necessary.

Supporting copy should be concise enough that large typography does not become crowded.

---

# Copy Density

This portfolio should be dramatically less wordy than the previous direction.

The visual experience should carry meaning.

Rules:

- no giant visible paragraphs
- no case-study wall of text
- no repeating explanation of the same project
- no résumé bullets copied directly into the main journey
- no long technical architecture descriptions by default

A scene should generally expose no more than about 40–60 visible words.

Many scenes should expose much less.

---

# Whitespace

Whitespace is an active design material.

It should:

- create calm
- emphasize scale
- improve pacing
- make complex scenes feel more expensive
- separate visual worlds
- allow motion to breathe

Do not fill empty space because it feels unfinished.

Some scenes may intentionally contain large unused regions.

---

The base system should likely use:

- light or neutral background

- muted secondary tones

Exact values are intentionally not locked yet.

Project worlds may introduce local color.

# 3D Aesthetic

3D should feel custom and authored.

Avoid generic:

- chrome blobs
- glass spheres
- random abstract loops
- floating primitives
- demo-scene aesthetics
- stock "futuristic" objects

3D objects should have a reason to exist.

They may represent:

- identity
- project mechanics
- transformation
- personal interests
- chapter transitions

The preferred aesthetic is:

- clean silhouette
- strong form
- limited materials
- deliberate lighting
- readable at a glance
- visually strong from a few controlled angles

3D should not become noisy or hyperreal simply because it is possible.

---

# Generated Assets

Generated assets are a core part of the design system.

Matthew should not be required to manually model or illustrate specialized assets.

Astra or other approved generation systems may create:

- 3D objects
- rendered stills
- abstract identity objects
- project-specific assets
- personal still-life components
- textures
- visual layers
- transition elements

Generated assets must still be art-directed.

The design process is:

1. define scene composition
2. define what the asset must accomplish
3. write a precise brief
4. generate variants
5. select the strongest
6. optimize for production
7. test in context

Never design a scene around a random generated asset just because it looks interesting.

---

# Motion Aesthetic

Motion should feel:

- smooth
- controlled
- spatial
- intentional
- restrained
- responsive

Avoid motion that feels:

- bouncy by default
- gimmicky
- ornamental
- game-like where inappropriate
- over-eased
- excessively elastic
- constant

The best transitions should feel like one scene becoming another.

Examples:

- hero object rotates and becomes part of Projects
- Rankle objects separate into the next composition
- Plannr document fragments resolve into calendar tiles
- a large year passes behind content
- academic nodes assemble gradually
- personal objects separate into labeled items
- the final contact scene recalls the hero

---

# Static Composition Rule

A critical standard:

> **Every important scene should still look excellent as a still image.**

Motion should enhance composition, not rescue it.

If a screenshot taken at a random stable point looks broken, unfinished, or dependent on movement to make sense, the composition is not strong enough.

---

# Calm vs. Complex Rhythm

The site should alternate between:

- calm
- complex
- calm
- expressive
- quiet
- playful
- resolved

Do not place several high-energy scenes directly next to each other without a reason.

Complexity needs contrast.

A visual peak should be followed by a quieter section.

---

# Navigation Presence

Navigation should remain peripheral.

The persistent chapter index should not visually dominate the page.

At rest, it should be compact.

When expanded, it should feel precise and minimal.

Avoid:

- giant fixed headers
- conventional top nav bars
- sticky full-width navigation
- large persistent branding
- constant menu chrome

The content should own the viewport.

---

# Hero Direction

The hero is the strongest identity moment.

It should likely include:

- Matthew Blanke
- very large typography
- one dominant generated object
- small professional descriptor
- minimal supporting copy
- chapter navigator

The hero should not feel like a conventional personal introduction.

Avoid:

> Hi, I'm Matthew.

Avoid:

> I'm a passionate software engineer...

Avoid a large paragraph.

The composition should immediately communicate confidence and taste.

---

# Hero Object

The hero object should be original.

Possible directions:

- sculptural MB monogram
- abstract industrial identity object
- transparent acrylic form
- machined dimensional typography
- structural object derived from the letters M/B

Avoid:

- generic sphere
- random chrome torus
- glass blob
- meaningless floating geometry

The object should have a silhouette strong enough to become part of the brand.

It should be designed for:

- desktop composition
- mobile fallback
- controlled 3D rotation
- use across transitions
- possible callback in Contact

---

# Projects Direction

Projects should be understood quickly.

The project scene should answer:

- what is this?
- why is it interesting?
- what did Matthew build?
- where can I see it?

without demanding a long read.

Each flagship project should have:

- one dominant visual idea
- one concise explanation
- a small technical line
- a clear action

Optional deeper details may exist, but they should not dominate the scene.

# Project Identity vs. Portfolio Identity

The portfolio should have a strong global identity, but projects may temporarily take over.

Global identity comes from:

- typography
- spacing
- navigation
- motion quality
- scene pacing
- object lighting
- level of restraint

Project identity may come from:

- color
- object type
- motion character
- local composition

The site should feel like one author presenting different worlds.

---

# Responsive Art Direction

Mobile should be redesigned rather than compressed.

Desktop may use:

- stronger overlap
- larger 3D scenes
- more spatial separation
- richer pointer interactions

Mobile may use:

- simpler 3D
- rendered asset fallback
- more direct composition
- touch-first interactions
- reduced overlap
- tighter narrative sequencing

The experience should still feel premium on mobile.

It should not feel like a degraded desktop layout.

---

# Reduced Motion Art Direction

Reduced motion should preserve visual composition.

It should not simply freeze awkward intermediate states.

For each motion-heavy scene, define a stable reduced-motion composition.

Examples:

- hero object shown in its most readable pose
- Rankle tiles arranged statically
- Plannr transformation represented as a clear composed sequence
- education clusters already assembled
- personal objects already separated and labeled

Reduced motion should still look intentionally designed.

# Things to Avoid

## Generic Developer Portfolio

Do not use:

- terminals
- Matrix code rain
- code wallpaper
- glowing syntax
- floating technology icons
- skill bars
- contribution graphs as decoration
- fake command prompts

## Generic Modern SaaS

Do not use:

- Bento grids
- endless rounded rectangles
- glass cards
- gradient blobs
- generic feature sections
- testimonial-style layouts
- dashboard mockups by default

## Generic Experimental Web

Do not use:

- purposeless blobs
- random 3D primitives
- constant parallax
- cursor gimmicks everywhere
- scroll effects with no relationship to content
- overdone distortion
- unreadable typography
- motion that competes with navigation

## Generic Editorial Portfolio

Do not fall back into:

- long text blocks
- repeated metadata rails
- every section using the same grid
- article-like project case studies
- excessive publication metaphors

This is not the previous portfolio direction.

# Originality

The site should feel inspired by the reference set without resembling any single reference too closely.

The final visual system must use:

- original generated assets
- original scene layouts
- original project representations
- original motion choreography
- original typography choices
- original navigation treatment
- original transitions

If a design feels recognizable as a copied reference scene, redesign it.

---

# Art Direction Decision Test

Before approving a scene, ask:

### 1. Is there one clear visual idea?

If no, simplify.

### 2. Could some text be replaced by composition or motion?

If yes, reduce copy.

### 3. Does the scene look good while paused?

If no, improve composition.

### 4. Is the visual object meaningful?

If no, remove or replace it.

### 5. Is there enough negative space?

If no, simplify.

### 6. Does the motion communicate change?

If no, do not animate.

### 7. Does this feel like a template?

If yes, art-direct it further.

### 8. Is the scene too similar to the previous one?

If yes, vary the visual language while preserving global identity.

### 9. Would the scene still work without WebGL?

If no, meaningful content is too dependent on decoration.

### 10. Does this feel like Matthew's portfolio?

If not, the scene may be visually strong but contextually wrong.

---

# Final Creative Standard

The target is not:

> a technically impressive portfolio.

The target is:

> **a visually sophisticated portfolio whose technical sophistication is evident because the experience feels effortless.**

The visitor should notice:

- the object
- the composition
- the transition
- the project
- Matthew

before they notice the framework, animation library, or 3D renderer.

The engineering should enable the art direction rather than become the art direction.
